# B-12 — View counter selalu 0 di produksi (+ sisa T-08)

**Prioritas:** 🔴 P0 · **Estimasi:** kecil · **Commit:** `fix(biolink): B-12 view counter works on database cache store`

## Masalah
- Produksi memakai `CACHE_STORE=database`. `DatabaseStore::increment()` mengembalikan `false` dan **tidak membuat key** bila key belum ada. Akibatnya `bio_views:{profileId}:{date}` tidak pernah tercipta → statistik views selalu 0. Test lolos karena phpunit memakai store `array`.
- `biolinks:flush-views` hanya memproses tanggal **hari ini** → view menjelang tengah malam hilang.
- Daftar `bio_views_pending:{date}` di-update dengan read-modify-write → bisa kehilangan ID saat ramai.

## File
- `app/Http/Controllers/PublicBioLinkController.php` → method `recordPageView()`
- `app/Console/Commands/FlushBioViews.php`

## Yang harus dilakukan
1. `recordPageView()`:
   ```php
   $cacheKey = "bio_views:{$profile->id}:{$today}";
   Cache::add($cacheKey, 0, now()->addDays(3)); // buat key bila belum ada (atomic)
   Cache::increment($cacheKey);
   ```
   Hapus seluruh logika `bio_views_pending`.
2. `FlushBioViews::handle()`:
   - Proses tanggal **kemarin dan hari ini**.
   - Iterasi `OfficerBioProfile::pluck('id')` (jumlah profil kecil) — tidak perlu daftar pending.
   - Untuk tiap key: `$views = (int) Cache::get($key, 0); if ($views > 0) { Cache::decrement($key, $views); ... increment 'views' di bio_daily_stats untuk stat_date yang sesuai }`. Pakai `decrement`, **bukan** `pull`, agar view yang masuk di antara get dan hapus tidak hilang.
3. Pertahankan filter bot yang sudah ada.
