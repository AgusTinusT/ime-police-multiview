## Skema yang dibutuhkan
**Kolom baru `officers`:**
| Kolom | Tipe | Fungsi |
| :--- | :--- | :--- |
| `callsign_normalized` | string(50), stored generated `UPPER(TRIM(callsign))`, index | cek unik cepat |
| `owner_updated_at` | timestamp nullable | import/sync tidak menimpa data pemilik |
| `callsign_changed_at` | timestamp nullable | batas ganti callsign 1×/7 hari |
| `avatar_is_custom` | boolean default false | sync YouTube tidak menimpa avatar |

**Tabel `officer_change_requests`:** `id`, `officer_id` (FK cascade), `requested_by` (FK users cascade), `field` string(40) (`rank_id`|`agency_id`), `old_value` string(150) nullable, `new_value` string(150), `reason` string(255) nullable, `status` enum(`pending`,`approved`,`rejected`,`cancelled`) default `pending`, `reviewed_by` (FK users set null) nullable, `reviewed_at` nullable, `review_reason` string(255) nullable, timestamps, index (`status`,`created_at`).

**Satu pending per officer per field** — gunakan pola yang portabel MySQL + SQLite:
```php
$table->unsignedBigInteger('pending_officer_lock')
    ->virtualAs("CASE WHEN status = 'pending' THEN officer_id END")->nullable();
$table->unique(['pending_officer_lock', 'field'], 'uq_change_one_pending');
```
(Jangan pakai `CONCAT`/`IF` — `CONCAT` tidak tersedia di semua versi SQLite.)

`down()` wajib menghapus semuanya.

## Model
`OfficerChangeRequest`: fillable sesuai kolom, relasi `officer()`, `requester()` (`requested_by`), `reviewer()`. Tambah di `Officer`: relasi `changeRequests()`; cast `owner_updated_at`, `callsign_changed_at` datetime, `avatar_is_custom` boolean.

## Command `officers:report-duplicates`
Tampilkan tabel callsign (berdasarkan `callsign_normalized`) dan `badge_number` yang dipakai lebih dari satu officer **aktif**, beserta ID & nama officer. Exit code 0; hanya laporan, tidak mengubah data.
